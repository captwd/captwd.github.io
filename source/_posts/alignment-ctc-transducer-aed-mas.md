音频一段几百上千帧，转写文本几十个字，而"第 37 帧对应哪个字"这种帧级标注永远不存在。识别要"多对少"（把帧压成字），合成要"一对多"（把字铺成帧），中间都隔着一道未知的对齐。这篇把 ASR/TTS 领域对这同一个困难的四种回答放进一张图里看。

## CTC：把所有合法对齐**求和**

CTC（Connectionist Temporal Classification）的三步：

1. 加一个特殊符号 **blank ␣**，模型对每一帧输出"字表 + blank"上的分布；
2. 定义折叠规则：**合并连续重复 → 删掉 blank**；
3. 损失 = 所有折叠后等于转写标签的逐帧路径概率**之和**（前向-后向 DP 高效计算）。

```
转写 "hi"，8 帧，三条候选逐帧序列：
  t:  1  2  3  4  5  6  7  8        折叠后        结果
     h  h  ␣ ␣  h  i  i  ␣          h,i           "hi"  ✓ 合法路径
     ␣ ␣  h  h  ␣  i  i  ␣          h,i           "hi"  ✓ 另一条对齐
     h  i  ␣ ␣  h  i  ␣ ␣          h,i,h,i      "hihi" ✗ 不合法

损失 = −log Σ_{折叠后="hi"的所有路径} Π_t P(token_t | 帧_t)
```

这就是"**对齐被边际化进损失**"的准确含义：逐帧分类器只给"每帧是什么字"的概率，转写标签允许无穷多种帧级对齐，CTC 不挑某一种，而是把它们的概率全加起来当这句话的概率，直接最大化它。对齐没有任何监督，是在求和过程中隐式学出来的。blank 的作用：让相邻相同字（"妈妈"）成为可能，并吸收静音帧。

要点与软肋：每帧预测**条件独立**——CTC 内部没有语言模型，纯声学逐帧分类，所以推理常配外部 LM 做 beam search。

## Transducer：求和 + 内部语言模型 + 可流式

RNN-T 把 CTC 缺的语言能力缝了回来，同时保住流式能力。三个部件：

```
已输出的 token 历史 y₁…y_u
        │
        ▼
 Prediction Network（小自回归 LM，消费已出 token）
        │ p_u
        ▼
音频帧 h_t ──► Joint Net: Linear(ReLU(h_t + p_u)) ──► softmax over {字表 ∪ ␣}
                                                          │
                        ┌─────────────────────────────────┴──────────┐
                     出字 y_{u+1}                                  blank ␣
                     历史前进（u+1）                              时间前进（t+1）

损失 = 在（时间 T × token U）网格上，对从 (0,0) 走到 (T,U) 的
      所有"出字/blank"路径求和 —— 又是对齐边际化，网格上 DP
```

每个时刻要么出字（prediction network 前进、时间不动），要么出 blank（时间前进、历史不动）。和 CTC 一样对齐求和，但多了 prediction network 这个**内部语言模型**（精度远超 CTC），且决策只依赖过去——**天然支持边听边出字**。Google 语音搜索、端上识别的工业标准。

## AED：让注意力学软对齐

attention encoder-decoder（Whisper 这类）是第三种哲学：不显式求对齐，让注意力权重自己学。

```
wav ──► Encoder（双向，必须看完整句） ──► H（全句帧记忆）
                                            ▲
                                            │ cross-attention：每个解码步对 H
已生成 token ──► Decoder（自回归） ──────────┘  加权查询，权重 = 对齐概率
        │
        ▼  逐字生成下一个 token
```

对齐以累积注意力的形式隐式存在，精度历史最佳；代价是 encoder 要看整句才能开始解码——**非流式**。它也是自回归的：对齐错一处，后续合成/识别连锁受损。这正是非自回归模型（Glow-TTS → Matcha 一系）引入 MAS 的动机：把"学内容"和"定对齐"解耦。

**Whisper 是个值得单列的例外**：不走自监督预训练，68 万小时弱监督数据直接端到端 AED。和 wav2vec2/HuBERT 路线的哲学分野在于——**自监督省标注，大数据换标注**，两条路最后都通了。

## MAS：TTS 侧的"取最大"

Matcha/Glow-TTS 一系的 MAS（Monotonic Alignment Search）面对同一道考题，答案是**取最大而不是求和**：

```
音素序列 ──► TextEncoder ──► mu_x（每音素条件向量） + logw（预测的对数时长）
真实 mel y ──┐
            ▼
逐（音素,帧）打分 log N(y_帧 | mu_x_音素) ──► DP 取最大似然"单调路径" attn
                                                    │
                                                    ▼
                          attn 折算出"教师时长" logw_ ──► L2(logw, logw_)
                          （时长预测器被蒸馏出来；推理时不再需要 MAS）
```

假设每帧 mel 服从对角高斯，路径得分 = 路径上各 (音素， 帧) 对的 log 似然之和，可以预先把所有配对的打分算成一张表，然后一遍 DP（每格只许"向右/右下"转移，保证单调）取全局最优路径。关键设计：**对齐不回传梯度，只当教师用**——它折算出的"教师时长"去训编码器自己的时长预测器。这是个自举结构：训练越久预测器越准，推理时就不需要 MAS 了，直接用时长的取整铺出对齐。

和 CTC 摆在一起：**一个对所有对齐求和，一个取最大似然对齐再蒸馏成时长预测器**。

## 全家福：一个上下游组合系统

```
      上游：自监督表征（三选一）              下游：任务 + 对齐范式（按任务）
┌────────────────────────────┐        ┌──────────────────────────────────┐
│ wav2vec2   对比 + 在线离散码   │        │ ASR:  CTC（求和，无内部LM，最轻）      │
│ HuBERT     掩码 + 离线kmeans │  ──►   │       Transducer（求和+内部LM，流式）  │
│ data2vec   回归 + EMA教师    │        │       AED（注意力软对齐，非流式，精度高）│
│ (emotion2vec=情感数据版)      │        │ SER:  池化 + 分类头                   │
└────────────────────────────┘        │ TTS:  MAS（取最大）+ 时长蒸馏（Matcha） │
                                       └──────────────────────────────────┘
```

## 一张卡片收尾

- **共同考题**：帧和字没有对齐标注。
- **CTC**：blank + 折叠 + 对所有合法路径**求和**；帧间条件独立，无内部语言模型。
- **Transducer**：同样**求和**，但带自回归内部语言模型，决策只依赖过去——可流式。
- **AED**：注意力学**软对齐**；精度高但非流式；Whisper 证明大数据弱监督也能走通。
- **MAS**：**取最大**似然单调对齐，蒸馏成时长预测器，推理时退场。
- 上游表征三范式（对比 / 离线伪标签 / EMA 回归）与下游对齐范式是正交的两层，可以自由组合。

Matcha-TTS 和 F5-TTS 这类流匹配 TTS，训练损失只有一个 MSE。第一眼看很难接受：生成一段语音，不应该是很复杂的事吗——对抗训练、噪声调度表、自回归逐字预测，怎么轮到流匹配就只剩下一个均方误差？这篇把这件事拆开。

公式全部采用 Matcha 的 `flow_matching.py` 和 F5 的 `cfm.py` 里的实际写法，两个仓库这两段代码几乎逐字相同。

## 从噪声到 mel：一条直线

训练数据里有一段真实 mel 频谱 `x₁`（80 通道 × T 帧），再采一捧同形状的高斯噪声 `x₀`。流的任务是把噪声搬运到数据，rectified flow 把这条路定义为**两点之间的直线段**：

```
x_t = (1 − t)·x₀ + t·x₁          # t ∈ [0,1]，逐元素的凸组合
```

这是"加噪声"的一步——想象一张频谱从雪花点里逐渐析出的过程：t=0 整张图是纯噪声，t=1 是干净 mel，t=0.5 时**每一个** bin 都恰好是一半噪声一半真值。每次训练随机抽一个 t，得到直线上的一个点。

## 一个采样同时造出输入和标签

速度场网络需要 (位置， 速度) 成对的数据，而直线在这里白送了标签——对 `x_t` 关于 t 求导：

```
d/dt [(1−t)·x₀ + t·x₁] = x₁ − x₀
```

路径是直的，速度沿路径**处处恒定**。于是两行代码同时给出训练输入和监督目标：

```python
y_t = (1 - t) * x0 + t * x1      # 题干：现在在哪
u   = x1 - x0                    # 答案：该往哪走、走多快
loss = F.mse_loss(v_theta(y_t, t, cond), u)
```

拿具体数字走一遍：某个 bin 上 `x₀=−1.2`、`x₁=0.8`、`t=0.25`，那么插值样本 `x_t = 0.75×(−1.2) + 0.25×0.8 = −0.7`，目标速度 = `0.8 − (−1.2) = 2.0`。网络的任务：给它 (−0.7, t=0.25) 和文本条件，猜出 2.0 这个方向。无数组 (x₀, x₁, t) 扫下来，网络学到的就是把噪声分布搬运到数据分布的场。

## "速度恒定"恒的是时间轴，不是空间轴

这里有个容易绕晕的地方。"直线速度恒定"说的是：**对固定的 (x₀, x₁) 这一对，速度沿 t 不变**——在 t=0.2 处问和 t=0.7 处问，答案都是 x₁−x₀。恒定是**时间轴上的性质**。

而频谱有 80×T 个位置，每个位置有自己的 (x₀, x₁)、自己的小直线、自己的那个恒定速度。一张 mel 的流，是 80×T 条互不相同的小直线并行发生。所以：

- **被广播的是 t，不是 v**。t 是钟，形状 (B,1,1)，整条频谱共享同一时刻；v 的形状是实打实的 (B,80,T)，逐元素各不相同，没有任何广播。
- 网络能给出逐元素不同的速度，是因为输入 `x_t` 本身就是完整的场——每个位置带着自己的混合状态，卷积/注意力还让它看得见邻居帧。元音帧和静音帧、低频段和高频段，"该往哪走"完全不同。

## MSE 不是"好用"，是"恰好选对"

更深一层的保证：同一个位置 x_t 可能来自**无穷多组不同的 (x₀, x₁)**，不同组给出的答案 x₁−x₀ 并不一样。MSE 回归的统计性质是最优预测等于**条件期望**，所以网络在每一点学到的是

```
v(x_t, t) = E[ x₁ − x₀ | x_t = x, t, 条件 ]
```

即"所有能到达这个位置的路径的方向平均"——而这恰好被证明就是**边际速度场**：沿它积分，概率路径与真实数据分布完全一致。换句话说，MSE 在这个框架里不是"工程上凑合的损失"，而是数学上恰好选对的损失。

## 训练与推理：同一个场的两副面孔

CFM 外壳本身没有可训练参数（网络挂在 `CFM.estimator` / `CFM.transformer` 上），它在两个阶段扮演不同角色，**调的都是同一个网络**：

| | 网络前向次数 | 输出拿来干嘛 |
|---|---|---|
| 训练一步 | 1 次（采一个 t，单点回归） | 和 x₁−x₀ 算 MSE，更新权重 |
| 推理一次合成 | n 次（n = ODE 步数） | 每次迈一步 `x += dt·v`，积分到 t=1 |

训练时执行的是 CFM 的损失构造逻辑，推理时执行的是它的 ODE 积分逻辑——"训练学场、用场"。

## 顺路解决一个工程问题：x1_hat

有些设计需要拿到"模型正在生成的 mel"——比如在生成的频谱上接一个辅助分类器。但 CFM 训练模式下模型从不生成完整 mel：每个训练步只做"采一个点、答一次速度、算个 MSE"。朴素解法是把整条 ODE 跑完，成本 ×n_timesteps，不可接受。

解法是一行算术：用网络自己预测的速度，把当前样本**外推到路径终点**：

```
x1_hat = y_t + (1−t)·v
```

直观含义：t=0.25 时，"当前位置 + 剩余路程比例 × 全程速度 = 终点估计"。把它和理想速度 u = x₁−(1−σ_min)x₀ 代数展开：

```
y_t + (1−t)·u = x₁ + σ_min·z
```

残差恰好是 σ_min 乘噪声——σ_min = 1e-4，比信号小四个数量级，可忽略。所以线性路径下这个反推**近乎精确恒等式**；用学到的 v_θ 时代价多一项 `(1−t)·(v_θ − u)`，即"剩余路程 × 速度预测误差"——训练早期 x1_hat 很糊，这是正常的。它的价值：零额外成本、可微，梯度能穿过它流回生成器。

注意方向：加噪声发生在构造 x_t 那一步；x1_hat 干的是**甩掉噪声估终点**，不是反过来。

## 尾注

这条"直线 + MSE"的框架还解释了流匹配 TTS 的两个工程特征：

- **为什么 10 步 ODE 就够**：路径几乎笔直，Euler 积分误差小；条件越充分（帧级文本条件、说话人、情感），流要搬运的随机性越少，路径越直。
- **为什么推理还能再快**：均匀时间轴可以重参数化——把步长挪到场弯曲最厉害的噪声端。实测见 [Sway Sampling 实测：少步数推理的收益与代价](/2026/09/13/sway-sampling-for-flow-matching-tts/)。
